# External oracles

- **DET-1:** replay identical capability inputs (including scheduling choices and atomic/mutex orders) with the same entry point and hash seed across interpreter/native runs. Observable results, effects and first failures must match. Randomise placement, allocator state, hidden addresses and task identities without exposing them. Run all corpus programs under deterministic Io simulation. The fixed-output witness is only a seed, not a proof of determinism.
- **DET-2:** run every check/run/fail test at every optimisation level and under single-definition, random and whole-program topologies. Compare first-failure rule/site, preceding effects, float bits, integer results, resource drop order and source allocation contracts. Include vector-chunk boundary failures when a SIMD surface exists. A single run cannot test equivalence between configurations.
- **DET-3:** compare accepted/rejected sets and runtime traces across flags, build modes, environments and topologies. Environment changes supplied through capabilities are different inputs and do not violate DET-1. The false-contract witness must remain a runtime failure in every build mode.
- **DET-4:** classify Unsafe code, FFI and environmental failures as outside the determinism oracle. The rule permits divergence there; it does not require a program to be nondeterministic. Audit the classification of effects and run launch/environment fault-injection tests instead of asserting an invented deterministic result.
