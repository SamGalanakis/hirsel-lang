# LANG coverage requiring another oracle

The `.hir` files cover settled single-program checks and observable behavior. V20 ratifies `bool`, `f64` and `pattern => expression` in the normative grammar. The items below distinguish external guarantees from tests blocked by missing specification. Issues are in [SamGalanakis/hirsel-lang](https://github.com/SamGalanakis/hirsel-lang/issues).

- **LANG-1, context-free grammar:** one accepted program cannot prove that parsing never consults types. Oracle: the parser API and grammar audit, plus parsing with arbitrary unresolved names. V20 section 23 assigns syntax and semantic diagnostic ownership. The grammar names @incomplete; marker and complete-caller twins cover todo. Parser implementation resource limits remain #33.
- **LANG-2, prefix law:** examples exercise contextual literals, operand/range context, local and parameter declaration order, indexing and generic call inference. The universal claim that every judgment depends only on the prefix and expected type needs a checker audit and differential checks after changing suffixes. Oracle: incremental checker dependency tracing and generated suffix perturbations.
- **LANG-3, temporary ownership:** the early-exit run test observes reverse drop order and that the callee is never entered. Caller ownership before entry, including failure unwinding and cancellation, additionally needs the ownership/RC model and failure injection; an ordinary source program cannot inspect the compiler's ownership slots. Observable output uses the exact-text contract in v20.
- **LANG-5, handles name external objects:** a copied handle must still name the same external thing. Oracle: simulated `Io` identity tests through two copies using the declared v20 library signatures. Source mutation places are covered by twins.
- **LANG-6, incomplete definitions:** marker and complete-caller twins use the ratified `@incomplete` spelling. V20 signature defaults are: MODE-7 modes, allocation allowed without `@noalloc`, absent brands/placement/contracts, authority from declared capability parameters, and an omitted result type means `()`. Oracle: grammar/checker fixtures for marked `todo` definitions, calls from complete definitions and explicitly incomplete callers. Current files use explicit result/parameter/field/constant types, MODE-7 mode defaults and `@noalloc` where the body warrants it. The fixed syntactic defaults are used rather than inferred from the body; omitted and explicit unit results both have controls. Independence from called bodies needs a dependency audit and body-replacement tests preserving signatures.
- **LANG-7, excluded feature syntax:** user type-class instances, macros and exceptions have no specified surface syntax. Oracle: grammar exclusion audit, then rejection fixtures for any spelling the grammar explicitly recognizes. Raw pointers use `Ptr[T]`; GEN-1 now tests their exclusion from data. Overloading, `any`, casts, exhaustiveness and implicit conversions have direct pairs. Size bounds admit equality only; independent/equal `Inline` sizes have direct controls rather than inventing size arithmetic constraints. Numeric conversion signatures are declared in v20.
- **LANG-9, runner selection:** test discovery/configuration still needs the runner harness. Ordinary std@1/test.property runs 100 generator/law cases and shrinks the first failure; its source, resource cleanup, seed/case reports and replay are checked by driver and runtime tests, and snapshot comparison and blessing by the CLI tests. A function taking another capability is an ordinary function, so it must not be rejected merely because its name starts with `test`.
- **LANG-10, loop lowering, owned slots and deterministic Depth:** the run test demonstrates self tail recursion with a finite result, but cannot observe the guaranteed loop or a single count operation per call. Oracle: lowering/RC instrumentation for self tail calls, recursion modulo constructor and owned-temporary borrowed arguments; ensure a current-frame borrow inhibits tail lowering. Exact `Depth` boundaries and their source attribution are blocked on #16's frame-byte limit and accounting. Use a logical-frame model once specified, rather than an arbitrary iteration threshold or native stack measurement.
- **LANG-14, prefix forms:** keywords are tested individually in a parameter-name position. Missing alternate surface spellings are a grammar exclusion audit, not a license to reserve unlisted ordinary identifiers.
- **LANG-15, closure binding context:** scoped literal and escaping typed binding twins use the ratified function-type spelling. Generic implicit move and borrowed binding diagnostics overlap OWN/MODE/CLO; their rule selection follows v20 section 23. Oracle for borrow lifetime/escape cases: the mode checker plus closure tests; no new ownership rule is invented here.

## Spec examples

The corpus includes `saxpy`, `Percent`, boxed `Tree`, labelled `rename` calls, label-before-mode calls, `copy`/`take`/`unique`, Result error mapping, ordinary test functions and the `test.dir` fake pattern. V20 publishes the sequence, file, task and overview transaction signatures and their support types. These examples remain integration fixtures for the prelude and simulated capabilities; runtime behavior must be exercised when those implementations land. Generated-body syntax remains reserved for a future revision (#5); `shape(T)` is covered under CT-3.
