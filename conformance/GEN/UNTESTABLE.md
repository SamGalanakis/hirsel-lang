# GEN coverage requiring another oracle

Issues are in [SamGalanakis/hirsel-lang](https://github.com/SamGalanakis/hirsel-lang/issues). Check-only files use declared parameter/result types, default modes from MODE-7 and LANG-6 v20 signature defaults.

- **GEN-1, opaque signatures:** bounds and authority summaries of opaque types must be declared and respected outside their module. External access remains blocked on #4's package/module fixtures; v20 supplies complete and explicitly empty opaque summaries. Oracle: public opaque types exposing each structural bound, with accepted/rejected external instantiations and authority checks. The `data` exclusion for raw pointers now has twins using the grammar's ratified `Ptr[T]`. Direct tests cover functions, capabilities, resources, handles, arenas, nested floats, all named bounds, unbounded borrow/move/drop, inherited distinct bounds and IEEE float equality. No universal equality is assumed. Container and closure summaries also require the ownership/mode/authority corpus's aggregate fixtures.
- **GEN-2, dictionary purity, non-derived Order and identity everywhere:** v20 declares Order.compare, Hasher.hash, Eq.equal and named scalar orders, with no implicit derivation. User records and function authority restrictions exercise the checker; generated dictionary/library fixtures must audit every callback and instantiation. Oracle: dictionary library checker fixtures and PROV brand checks for same/different dictionary identities. Top-level dictionary identity across modules additionally needs #4's multi-package fixtures. Do not invent Order fields or accept an arbitrary record as a built-in Order.
- **GEN-3:** reserved for future type-shape reflection (#5). V1 requires no executable shape-inspection or derive/body-generation API.
- **GEN-4, layout and FFI monomorphism:** generic `@noalloc` identity, inline record and tuple construction are checked, but no source operation can inspect hidden generic boxes. Oracle: TIR/LIR layout inspection for each instantiation, verifying identical layout to the substituted type and absence of implicit allocation calls; allocation instrumentation across topologies. FFI/exported-C rejection twins are blocked on #6's `unsafe ffi` metadata and exported-C syntax (also #4). Once defined, accept monomorphic externs/exports and reject generic ones without introducing another interop violation.
- **GEN-5, topology-independent verdict and diagnostics:** self-growing and mutually growing cycles reject; acyclic growth, constant recursion and a cycle whose growing edge is followed by a shrinking edge accept. Oracle: the instantiation-graph checker plus the same fixtures under whole-program, per-definition and random unit partitions. V20 selects the earliest growing edge by canonical source order; compare the same diagnostic across every partition.

- **GEN-1/MEM-5, generic resource destruction:** generic discard is permitted but has no @noalloc promise. A taken unbounded T can have an allocating user destructor. V20 declares @noalloc drop and noalloc_drop and adds concrete/generic/field cleanup pairs. Oracle: extend those fixtures to every normal/error/failure/cancellation path and compare allocation traces.
