# Counted microbenchmarks

Instructions are the verdict. Each sample starts a fresh process pinned with
`taskset`, under `perf stat -e task-clock,cycles,instructions,cycles:u,instructions:u`.
All participants run once per round in a seeded shuffled order (10 rounds by
default). Any mixture of Hirsel, Rust and C executables works. Linux `perf`,
`taskset`, Python 3.11+, and permission to count hardware events are required.
Missing or unsupported counters fail the run. A failed session preserves its
completed samples and error in JSON, with `status: "failed"` and no verdict;
failed sessions cannot be used as comparison baselines.

Write a JSON list for **one workload and identical input** (commands are argv,
never shell strings). Paths resolve from the invoking directory; optional `cwd`,
`env` and `stdin` apply per participant. All stdout checksums must agree across
participants and rounds before a verdict is issued. Print workloads go to a
file while running; their output is hashed and discarded afterwards.

```json
[
  {"name": "rust", "command": ["/tmp/micro/rust", "strbuild", "2000000", "1"]},
  {"name": "old", "command": ["/tmp/old-strbuild", "--hirsel-grants", "bench/micro/grants.json", "2000000", "1"]},
  {"name": "new", "command": ["/tmp/micro/strbuild", "--hirsel-grants", "bench/micro/grants.json", "2000000", "1"]}
]
```

Run a session (each sample invokes `tools/capped` separately; run the harness directly):

```sh
bench/micro/run participants.json --output session.json --reference rust --seed 42
```

The text table and JSON report instruction ratios (total and user), total cycles
ratios, total and user IPC, and task-clock ratios with a paired-round bootstrap
95% CI (5,000 seeded resamples of rounds, ratio of medians). A ratio above 1
means more work/cycles/time than the reference. Both privilege levels are shown
because kernel-heavy workloads such as print can disagree in user and total
counts. The CI describes within-session jitter; it does not bound host drift
or correlated contention across rounds.

Every sample records raw before/after `/proc/stat` tick snapshots for every SMT
sibling and its busy fraction during the sample. Perf pre/post hooks take the
snapshots inside the capped slot, excluding queue time and capped startup.
Idle and iowait ticks count as idle; guest ticks are not double counted. A zero
tick interval is `null`. No busy samples are silently excluded. Counter running
percentages expose perf multiplexing. Session ID, seed, CPU, argv, executable
SHA-256 and output SHA-256 are retained. The harness holds
`/workspace/code/hirsel-briefs/locks/cpu31-timing.lock` over the whole CPU31
session; capped slots are held only for individual processes. Other CPUs use
`/tmp/hirsel-micro-cpuN.lock`. These locks serialize cooperating measurements;
they provide no core isolation.

Compare a saved session's **instruction counts only**:

```sh
bench/micro/run participants.json --output next.json --compare session.json --seed 42
```

The saved-session section contains only instruction ratios for matching names.
Cross-session time and cycles comparisons are refused. To compare old and new
time, include both executables in the same participants list.

Build one workload at LLVM O3 and its Rust pair (pool-built release CLI/precheck and runtime, separate
capped compiler invocations; output directory may be outside the worktree):

```sh
bench/micro/build strbuild --size 2000000 --output /tmp/micro
```

Run the generated pair list directly:

```sh
bench/micro/run /tmp/micro/strbuild.json --output /tmp/strbuild-session.json --seed 42
```

The promoted scratchpad programs are in `programs/`; `rust/main.rs` dispatches
by case name. CLI-built Hirsel executables require explicit launch grants:
`--hirsel-grants bench/micro/grants.json N [epochs]`; Rust argv is
`case N [epochs]`. The supplied template grants stdout and cooperative tasks,
with zero seeds and no directory access.
Epochs default to 1 on Hirsel and are required on Rust except print/channel.
Use the same epochs on both; each epoch changes the salt and contributes to a
wrapping checksum. Harness rounds are independent process samples.

| case | suggested N | workload |
|---|---:|---|
| `strbuild` | 2000000 | decimal strings appended to a builder, FNV checksum |
| `sha` | 33554432 | SHA-256 of generated bytes, first eight digest bytes |
| `print` | 1000000 | identical formatted lines; no epochs argument |
| `sort` | 1000000 | xoshiro-generated u64, unstable sort, checksum |
| `map_u64` | 1000000 | integer-key inserts and gets |
| `map_str` | 2000000 | 4,096 string-key counters |
| `map_remove` | 20000 | insert then remove all integer keys |
| `map_str_upsert` | 2000000 | same counter using one upsert per selection |
| `json` | 20000 | construct JSON, then ten std parse/stringify/drop round trips |
| `channel` | 100000 | two-channel ping-pong, sum of replies; no epochs argument |

The first seven pairs were promoted from perfsmash-rt's 2026-10-19 scratchpad.
The channel pair extends the existing `LANG-9-test-tasks-ping-pong` corpus
example. Hirsel uses cooperative scoped tasks; Rust uses std mpsc and one
worker thread. Affinity is inherited by the worker, so both share one CPU.
This compares the two implementations, including their scheduling costs.

Build a compiler with release optimization, line tables and frame pointers:

```sh
.buck2/bin/buck2 build --target-platforms //tools/buck2:profiling //:hirsel-toolchain --show-full-output
```

Record one compile using the printed bundle path, then inspect its stacks:

```sh
flock /workspace/code/hirsel-briefs/locks/cpu31-timing.lock tools/capped taskset -c 31 perf record -g -o /tmp/hirsel.perf -- <bundle>/hirsel check examples/todo-api/hirsel.json && perf report -i /tmp/hirsel.perf --no-children --stdio | head -50
```

The profiling platform applies release codegen/reservations to first-party and
third-party compiler code. Runtime archives retain their native target profile;
this recipe profiles compiler execution.

The `json` pair uses std `json` and serde_json 1.0.151 with `Value` (default
features). It checks the total serialized byte length; object field ordering
differs but lengths agree. This is separate from `bench/native`'s lossless
spelling-preserving JSON algorithm. `map_str` preserves the original two-probe
source; `map_str_upsert` measures the collections API introduced afterwards.

See [http/README.md](http/README.md) for the finite HTTP keep-alive pair and its
independent open-loop client.

The additional JSON and upsert programs live in `programs/extended/`; the existing
Cachegrind budget set remains the eight top-level programs. `build` discovers
both directories. The serde_json reference has its own sibling Buck2 package,
[../micro-json-reference](../micro-json-reference/README.md).

The [post-perf remeasurement](reports/perf-remeasure-2026-10-19.md) records
all native pairs and these micros, with current instruction gaps and limits.
