# Bitwise CRC32: unsigned mask lowering

Accepted source-local improvement on base `8bedce64d25ba757e6bf5a14ebb10423703d180c`.
The benchmark still performs eight reflected IEEE `0xedb88320` recurrence
steps per byte, in the same order, starting and finishing with the same
complement. Only `hash.hir::crc32` changes: `u32.wrapping_sub(0u32, crc & 1u32)`
produces either zero or all ones, selecting the polynomial without a source
conditional. Subtraction explicitly wraps; checked unsigned underflow would
be incorrect. There are no table lookups, hardware CRC instructions, new
intrinsics, compiler passes, language rules, ABI changes or std changes.

## Ten-round instruction verdict

2026-10-22, x86-64 host; seed `2026102209`. All four participants ran once
per round in shuffled order, with unchanged full `run.js` CRC configuration:
one million RNG-generated bytes, seed 42, 150 timed iterations and 30 warmup
iterations, checksum `2318723244`. All 40 processes passed. The Rust adapter
uses the identical RNG and 180 calls, with `black_box` to retain each input
read. It omits the unrelated upstream registry and JSON/time protocol;
therefore its process totals explain compiler output, not a replacement
measurement of the published whole-suite Rust anchor.

The winning form removes **26.3912% of process instructions** (1.35853x
fewer instructions). The 14-instruction loop reduction predicts 2.52 billion
removed instructions across 180 million bytes, close to the observed
2.533 billion difference. This is instruction evidence, not a wall-time
speedup claim.

Each process ran through `taskset -c 5 nice -n 10 perf stat --no-big-num -x ';'
-e cycles,instructions,branches,branch-misses`. All counters reported 100%
running. Counts cover the pinned process, its inherited descendants, startup,
input preparation, warmup, timed work and teardown, including kernel work;
there is no task-scoped counter subtraction. CPU5's SMT sibling is CPU21;
background contention was not controlled. CPU31 was never occupied. An
immediate nonblocking check found the CPU31 timing lock free, but this lane's
restriction against using reserved CPU31 was retained. CPU5 had no exclusive
timing lock, so cycle medians (4,604,269,152 before; 3,138,055,240 mask) and
printed times are diagnostics only. Exclusive wall-clock timing remains open.

Both Hirsel loops have one byte-loop branch and no data-dependent bit
branches. Baseline uses eight `test`/`cmov` selections. The mask allows LLVM
to combine independent polynomial contributions using scalar masks and SSE2
shuffles/xors. The source remains eight ordered recurrence steps. Rust
1.99.0 (`b940084d7`, LLVM 23.1.1) recognizes the unchanged upstream recurrence
and emits a 256-entry lookup table and a byte loop unrolled by two. That is
an LLVM transformation, not a source algorithm difference. Hirsel uses its
pinned LLVM 21 toolchain. Closing the remaining Rust gap requires separate
compiler investigation; no table implementation was substituted here.

Formatting removes redundant mask-expression parentheses. Rebuilding that
final source produces a different whole binary identity, while its complete
142-byte CRC hot loop is byte-identical to the measured mask executable:
SHA-256 `c592f9a61667a308d31e955f6d0963a1acc2217e6dc5b6a66b184a13232160fb`.
The formatter's precedence therefore does not change the measured lowering.

## Correctness and allocation scope

`gate-langarena` retains its existing Python harness; one import registers
`CRC32Recurrence`. Its selector runs the extracted scored function on H,
LLVM and Cranelift. There are 78 rows per backend: all 33 Go IEEE golden
rows (including the two long rows), empty input, `123456789`, all 256 byte
values, lengths 0–33 and 63/64/65/127/128/129/255/256/257, and seeded binary
payloads. Short rows test every prefix and split point, 3,509 positions in
all. Every prefix agrees with the bitwise reference and independent
`std.crc32.digest`; every split continues both the bitwise test copy and
`std.crc32.update`, including an empty update. The test-only continuation
copy changes just the initial finalized checksum parameter and its complement.
The scored function remains verbatim. Python's bitwise oracle also agrees
with zlib. Session checks independently queried the compiled Rust bitwise
reference for every one of the 3,509 prefixes.

Baseline and final: 3 Python wrappers passed each, executing 234 Hirsel
row tests each (78 per backend). The final scoped Buck2 target passed with
zero failures, skips or zero-selection executions. Both small benchmark
checksums (`CRC32=3031698216`, toy `SHA256=1036619072`) and both full
checksums (`CRC32=2318723244`, toy `SHA256=2844672256`) pass. SHA256 source
and algorithm are unchanged. The first baseline experiment used an explicit
unbounded CLI interpreter budget; final registered tests use the existing
CLI default, with no cap change or corpus registration.

Allocation evidence uses separate measurement-runtime executables, with
regions disabled by the existing source-profile tool. The fixture extracts
the exact before/after CRC bodies, prepares the same million-byte input,
runs 180 recurrence calls and asserts checksum `2318723244` internally.
Both preparation runs report 17 allocations and 17 frees, all attributable
to input construction; CRC contributes zero allocation sites. The ten-round
allocation result is recorded in the lane report. This covers runtime heap
operations of the recurrence and its input builder; it excludes the JSON,
file, clock and reporting harness, host/system allocator bookkeeping, and
Rust allocations. These instrumented binaries supply no timing evidence.

## Prior art and adaptations

The recurrence is LangArena `rust/src/benchmarks/buffer_hash_crc32.rs:4–18`,
commit `3c9f84ddaeec834c0631747cb789e8cfd602f993`; expected small checksum is
`test.js:195–201`. Its MIT notice/license is retained in this directory's
`LICENSE`. Go `src/hash/crc32/crc32_test.go:40–74,234–258`, commit
`ebe2feefc400f813aefdc8a036e66d2619da6649`, supplies IEEE golden vectors and
split cross-check structure. Copyright 2009 The Go Authors, BSD-3-Clause;
the full notice is already retained in `third-party/NOTICES.md`.
`stdlib/std@1/crc32.hir` and Go's slicing code remain read-only independent
oracles. Go Castagnoli fields and serialized internal-state fields are
omitted because this lane tests IEEE recurrence and public split updates.
Seeded binary/cutoff vectors extend Go's coverage. The Rust adapter adds hex
input/output and a black-boxed frozen-config driver, without changing its
recurrence. The unsigned wrapping mask is the sole scored-source adaptation,
justified by the measured instruction reduction above.
