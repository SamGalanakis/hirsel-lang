<a id="cause-cold"></a>
**cold**: Local runtime initialization: eagerly decode/allocate the complete failure-site table before serving (isolate::decode::text and UTF-8 validation appear in the cold user-instruction profile; heaptrace shows 30,995 text allocations). Loader, allocation/free and cooperative admission also appear. Trigger: an empty board, start the release binary and GET /. The profile does not establish an additive explanation of every kernel cycle.

<a id="cause-restart"></a>
**restart**: Local loading/rendering: parse the generic JSON tree, map fields into Board, then deep-copy the board for the first filtered response. The restart user-instruction profile contains json_node/json_quoted, map_probe/map_get, seq_grow, copy_graph and append_case. Trigger: load the provided 10k snapshot and GET /?q=Task+9999. The persistence snapshot format is shared; this is implementation work, not a durability mismatch.

<a id="cause-list"></a>
**list**: Local rendering/snapshot implementation: board_snapshot requests a unique deep copy before read-only rendering; HTML construction grows and copies byte sequences. The list profile contains memcpy/memmove, copy_graph/clone_block, unique_copy_value, seq_grow and text.append; the heap profile resolves copied storage to board_snapshot. Trigger: GET / over the 10k seed. No evidence that this gap is a fundamental language requirement.

<a id="cause-search"></a>
**search**: Local Unicode/string and snapshot work: ASCII text still takes string.append_case's Unicode-table path for each scalar of each scanned task; board_snapshot additionally deep-copies the board and hashes graph-copy entries. The search profile names append_case, copy_graph, clone_block, Copies::get/insert and DefaultHasher. Rust uses the same Unicode16 data with an ASCII fast path. Trigger: GET /?q=Task+9999&sort=priority over 10k tasks.

<a id="cause-create"></a>
**create**: Local snapshot serialization: each mutation constructs generic JSON maps for all 10k items before byte encoding; json_write_text, decimal.append, map_prepare, unique_copy_value and release_block appear in the create profile. Rust's serde encoder serializes the typed snapshot directly. Trigger: POST /tasks with the benchmark draft over the 10k seed. Both save compact full-board files with the same volatile durability.

<a id="cause-update"></a>
**update**: Local snapshot serialization/copying: a one-item edit rebuilds generic JSON maps for every item, with map_index/map_insert/map_probe, item_to_json, byte-list growth, unique_copy_value and page/copy work in the update profile. Trigger: POST /tasks/1 with the benchmark form over the 10k seed. The common full-snapshot persistence policy contributes O(N) work to both implementations; the measured gap is in how that work is implemented.

<a id="cause-sse"></a>
**sse**: Architectural fan-out policy plus local costs: each subscriber independently scans/renders the whole board; Hirsel also deep-copies its board per subscriber and keeps that snapshot in scope across channel.receive. The SSE profile contains append_case and graph-copy/hash work; heaptrack resolves about 489 MB of peak allocations at 100 clients to board_snapshot -> unique_copy_value -> copy_graph/clone_block. Trigger: 100 GET /updates streams with text=Task 9999 over 10k tasks, then POST /tasks/1/advance. Shared rendering for identical views would change fan-out architecture; avoiding retained copies and accelerating ASCII folding are local improvements. The 1000-client row is unavailable at the unchanged 4 GiB cap; sse-memory owns the fix.

<a id="cause-heap"></a>
**heap**: Local snapshot lifetime/copying and allocator high-water retention: the 100-stream heap profile attributes the dominant storage to board_snapshot -> unique_copy_value -> copy_graph/clone_block, with slab refill and large allocations; smaps confirms ordinary private heap, not committed fiber stacks, dominates. Trigger: the common 10k seed, GET / and 100 selective SSE subscriptions. Idle rows also include JSON loading plus the first response; the combined profile identifies mechanisms, not an exact additive accounting of each RSS row. Cold-start metadata is described separately. No fundamental requirement to retain a full independent board per idle stream was established.


Minimal triggers use the fixture generated by `fixture(data, 10000)` and routes shown in each attribution. CPU profiles contain limited samples for short operations and incomplete unwinds across native fiber switches; flat symbol attribution is stronger than their full call chains. Causes identify measured mechanisms, not a percentage decomposition of every gap.

CPU and latency evidence comes from separate `perf record` runs; heap evidence is a separate heaptrack run over the same 10k seed and a full list render plus 100 SSE subscriptions. Neither profiling run contributes timing comparisons.
Low offered-rate cells have few requests: histogram tail values are empirical order statistics, not a claim of a production tail-latency bound. CPU15 busy samples are retained; time/cycle conclusions require an idle-sibling rerun when interference is present.
