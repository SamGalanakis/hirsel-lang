# Implementing tabfold

`main(rt: Io, args: Args)` requests only Args, stdout, Tasks and the read-only
Dir mounted at `data`. `cli.parse_interspersed` retains original zero-based argv
indices for flag errors. File errors retain the one-based operand ordinal and
underlying FileError; parse errors retain operand ordinal and one-based line.

Read at most `jobs` files in operand order using `file.open` and
`file.read_all_bounded(d, mut f, 65536)`. A bounded read distinguishes Limit from
File errors and probes for overflow. Submit the inert bytes and ordinal to
`task.map_all(tasks, take batch, 1, model.reduce)`: one pure worker per file,
with at most jobs workers. Even jobs=1 uses the same scope/join path and is a
sequential control. No worker owns authority. Merge only after the complete
batch succeeds, in input order. Failed runs never render or write stdout.

The parser scans LF-delimited records, strips CR only immediately before LF,
and rejects empty records, invalid UTF-8, keys outside 1..128 bytes, extra tabs,
and integers outside signed decimal [-1000000000,1000000000]. Empty files and
an optional final newline are valid. At most 1024 records fit in a file.
Checked i64 sums and u64 counts also guard merges. Sort keys with
`string.compare` (UTF-8 byte order), then use `csv.write_record` for every row.
Buffer the entire CSV and call `out.write` once after all inputs succeed.

The success-index/first-error/join structure adapts Go x/sync errgroup,
commit `1f920df1e8fcf601d1aaf0f2ea500e1d2ccce105`,
`errgroup/errgroup.go:45–100` and `errgroup/errgroup_test.go:65–136`
(BSD-3-Clause, Go Authors; fixtures/GO-LICENSE.txt). The indexed success,
empty/single/error controls are retained. Adaptations: bounded batches instead
of a semaphore; pure owned/inert inputs instead of shared mutable result slots;
Hirsel's shipped task.map_all/task.all supplies cancellation and joins. All
children join on scope exit. Bounded pure work may finish after cancellation;
there is no preemptive cancellation promise. The first completed error is
observed and replayed; competing invalid files have no promised race winner.

The local std task API at audit commit
`bbe8105de781b2995a1c907431fc03245433d6f5`, `stdlib/std@1/task.hir:1–33,49–119`,
is Hirsel authority, not an external port. CSV, CLI, bounded file reads, numeric
conversion and sorting use existing std APIs without copying implementations.
Fixtures and E2E assertions are independent literal expectations; no expected
CSV is generated by the implementation under test.

Run the package tests on each engine, then the standalone E2E target:

```sh
hirsel test examples/tabfold/hirsel.json
hirsel test --native --backend llvm examples/tabfold/hirsel.json
hirsel test --native --backend cranelift examples/tabfold/hirsel.json
python3 tools/buck2/prepare.py
.buck2/bin/buck2 test //:hirsel-cli-test-tabfold_10
```

The private verifier builds one native executable per backend and reuses it.
It checks jobs 1/2/4, input permutations, strict failures, byte limits, record
limits, unchanged hashes, and missing grants. It records success and malformed
input on each engine, hides inputs and grant files, and replays each observed
triple on all three engines. Only admitted `tasks.cooperative@1` is used;
logical concurrency is bounded, with no throughput or physical speedup claim.
See [native verification](../../docs/native-verification.md) for build/launch
and tape identity rules. Evidence and retained binaries belong outside the repo.
